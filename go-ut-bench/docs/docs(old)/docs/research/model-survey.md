# 模型能力调研

## 1. 调研目标

建立模型选型的工程参考，重点关注：

- 接口兼容性与接入复杂度
- 稳定性（超时、错误率）
- 生成效率（延迟、Token）
- 多语言适配能力

## 2. 当前接入模型（以配置为准）

### 启用模型

- qwen（`qwen3.6-plus`，DashScope 兼容 OpenAI 协议）
- deepseek（`deepseek-chat`）
- minimax（`MiniMax-M2.7`）
- doubao-seed（`doubao-seed-2.0-pro`）
- glm-4.7（`glm-4.7`，Ark 接入）

### 已禁用模型

- glm（旧配置，`glm-4`）
- kimi-k2.5（当前阶段禁用）

## 3. 接入协议与端点

- OpenAI 兼容：`/chat/completions`
- DashScope 原生：`/services/aigc/text-generation/generation`

项目中对 provider 做了协议适配，避免调用层散落分支逻辑。

## 4. 评估维度

### 4.1 可用性

- 是否能稳定返回结果
- 是否存在大面积超时或 4xx 错误

### 4.2 质量先验

当前仅完成生成阶段，质量先验通过以下信号间接观察：

- 生成成功率
- 返回内容结构稳定性（是否可解析为代码）

### 4.3 效率

- 单样本平均延迟
- 平均 Token 开销

### 4.4 成本可控性

- 在并发场景下的稳定性
- 重试后的成功率

## 5. 已观察到的工程现象（阶段性）

- 不同模型对长 Prompt 的容忍度差异明显
- 某些模型在复杂样本上更易超时
- 协议与端点的细微差异会导致系统性失败（如 URL/协议不匹配）

## 6. 选型建议（当前阶段）

- 先以“稳定返回 + 可持续运行”为第一优先级
- 对高超时模型先降并发/降输出长度再评估
- 生产化前必须补齐 Evaluator 指标闭环，再做最终质量结论

## 7. 后续调研计划

- 分语言统计成功率与延迟分布
- 分场景统计失败类型（超时、参数、内容解析）
- 增加成本维度（Token 与响应时间联合评估）
- 加入长期回归测试，观察模型版本变动影响
