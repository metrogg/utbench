# ut-bench 使用说明

本文档给出从环境准备到报告查看的完整使用流程，适合首次接手项目时快速落地。

## 1. 项目目标与流程

ut-bench 的主流程：

1. Runner 调用模型生成单元测试。
2. Evaluator 执行编译/测试/覆盖率/变异测试评测。
3. Reporter 输出中文可视化报告（JSON/CSV/HTML）。

默认推荐口径：Evaluator 使用 latest-only（每个模型+样本仅评最新测试文件）。

## 2. 环境准备

在仓库根目录执行：

```bash
python3 -m pip install -U pyyaml pytest coverage mutmut
```

或直接使用：

```bash
bash scripts/setup.sh
```

建议检查版本：

```bash
python3 --version
python3 -m mutmut --version
```

## 3. 配置模型与密钥

模型配置文件：`benchmark/config/models.yaml`

### 3.1 关键配置项

- `enabled`: 是否启用模型
- `provider`: 提供方
- `config.api_endpoint`: API 地址
- `config.model`: 模型名
- `config.api_key_env`: 环境变量名

### 3.2 设置环境变量（WSL/Linux）

```bash
export DASHSCOPE_API_KEY="你的 qwen key"
export DEEPSEEK_API_KEY="你的 deepseek key"
export MINIMAX_API_KEY="你的 minimax key"
export VOLCENGINE_API_KEY="你的 volcengine key"
```

验证是否生效：

```bash
python3 - <<'PY'
import os
for k in ["DASHSCOPE_API_KEY","DEEPSEEK_API_KEY","MINIMAX_API_KEY","VOLCENGINE_API_KEY"]:
    print(k, "set" if os.getenv(k) else "unset")
PY
```

## 4. 运行 Runner（生成测试）

### 4.1 小规模验证（推荐）

```bash
python3 -m benchmark.runner --lang python --max-samples 1 --reset-checkpoint
```

### 4.2 指定模型/语言

```bash
python3 -m benchmark.runner --model deepseek,doubao-seed --lang python --max-samples 2
```

### 4.4 一键执行完整流水线

```bash
bash scripts/run_benchmark.sh --model deepseek --lang python --max-samples 2
```

说明：该脚本会按顺序执行 runner、evaluator、reporter。

如需只评估白名单内可独立执行样本（推荐用于模型横向对比主口径）：

```bash
bash scripts/run_benchmark.sh --model deepseek,minimax,doubao-seed --lang python --only-self-contained
```

当前 Python 数据集为 4 条基线样本，可直接全跑：

```bash
bash scripts/run_benchmark.sh --model deepseek,minimax,doubao-seed --lang python --sample-glob "*_python_*_0.py" --max-samples 4 --reset-checkpoint
```

### 4.2.1 指定样本子集（按目录/模式）

例如仅跑 realworld 扩展集中 `boundary` 文件夹前 5 个：

```bash
python3 -m benchmark.runner \
  --lang python \
  --sample-glob "boundary/*.py" \
  --max-samples 5
```

如果你要“扩展集四个文件夹各 5 个”，执行四次：

```bash
python3 -m benchmark.runner --lang python --sample-glob "boundary/*.py" --max-samples 5
python3 -m benchmark.runner --lang python --sample-glob "complex_dependency/*.py" --max-samples 5
python3 -m benchmark.runner --lang python --sample-glob "interface_mock/*.py" --max-samples 5
python3 -m benchmark.runner --lang python --sample-glob "simple_function/*.py" --max-samples 5
```

说明：`--max-samples` 是“每个语言目录内”生效，所以与 `--sample-glob` 组合后，可精确控制子集规模。

### 4.3 断点续跑与并发

```bash
# 默认续跑
python3 -m benchmark.runner --lang python

# 禁用续跑
python3 -m benchmark.runner --lang python --no-resume

# 指定并发
python3 -m benchmark.runner --lang python --max-workers 8
```

## 5. 运行 Evaluator（质量评测）

### 5.1 默认模式（推荐）

默认只评每个模型+样本的最新测试文件：

```bash
python3 -m benchmark.evaluator --results-root results --lang python
```

### 5.2 指定模型

```bash
python3 -m benchmark.evaluator --results-root results --model deepseek --lang python
```

### 5.3 评估全部历史文件

```bash
python3 -m benchmark.evaluator --results-root results --lang python --all-history
```

输出文件：`results/evaluator_summary_*.json`

## 6. 运行 Reporter（生成可视化报告）

### 6.1 默认输出

```bash
python3 -m benchmark.reporter --results-root results
```

### 6.2 指定 evaluator 输入

```bash
python3 -m benchmark.reporter --results-root results --evaluator-summary results/evaluator_summary_xxx.json
```

### 6.3 常用高级参数

```bash
python3 -m benchmark.reporter \
  --results-root results \
  --formats json,csv,html \
  --chart-style teal \
  --threshold-test 0.7 \
  --threshold-line 0.7 \
  --threshold-branch 0.6 \
  --threshold-mutation 0.85
```

输出目录：`results/reports/`

- `reporter_summary_*.json`
- `reporter_by_model_*.csv`
- `reporter_by_language_*.csv`
- `reporter_samples_*.csv`
- `reporter_report_*.html`

## 7. 结果解读建议（重点）

### 7.0 样本分层（建议先看）

Evaluator/Reporter 会按 Python 样本分层输出：

- `self_contained`: 样本在 allowlist 内，优先作为模型能力主口径
- `non_self_contained`: 样本不在 allowlist，更多反映环境/依赖问题
- `unknown`: 无法识别分层（如源码路径缺失）

allowlist 文件：`benchmark/config/python_self_contained_allowlist.txt`

建议优先关注：

- `self_contained_compile_pass_rate`
- `self_contained_test_pass_rate`

### 7.1 正确性

- `compile_pass_rate`
- `test_pass_rate`

### 7.2 覆盖率

- `avg_line_coverage`
- `avg_branch_coverage`

### 7.3 变异测试（避免误读）

- `mutation_total_mutants`
- `mutation_killed_mutants`
- `mutation_survived_mutants`
- `mutation_not_checked_mutants`
- `mutation_kill_rate`（killed/total）
- `mutation_effective_kill_rate`（killed/(killed+survived)）

建议优先看 `mutation_effective_kill_rate`，并结合 `mutation_not_checked_mutants` 判断结果可信度。

## 8. 手工复核 pytest + mutmut（单样本）

如果需要手动核查某个模型某条测试：

1. 将源码与测试放到独立目录（如 `justtest/`）。
2. 先跑 `pytest -q`，确认测试本身可运行。
3. 配置 `pyproject.toml` 的 `[tool.mutmut]`。
4. 运行：

```bash
python3 -m mutmut run --max-children 1
python3 -m mutmut results --all true
python3 -m mutmut export-cicd-stats
```

5. 查看：`mutants/mutmut-cicd-stats.json` 与 `mutants/*.meta`。

## 9. 常见问题

### 9.1 runner 报缺失 key

提示 `Missing API key env var`，说明当前 shell 未设置对应环境变量。

### 9.2 报告中耗时/Token 有空值

多为历史测试缺少 metadata，报告会标注指标来源与缺失原因。

### 9.3 变异体总数>0但 killed/survived 很低

先看 `mutation_not_checked_mutants`，再看 `mutation_effective_kill_rate`，不要只看 `mutation_kill_rate`。

### 9.4 全仓 pytest 被实验目录影响

已在 `pytest.ini` 忽略 `justtest/mutants` 与 `results`，一般不会再污染。

## 10. 推荐执行顺序（实战）

```bash
python3 -m benchmark.runner --lang python --max-samples 1 --reset-checkpoint
python3 -m benchmark.evaluator --results-root results --lang python
python3 -m benchmark.reporter --results-root results
```

打开最新 HTML 报告：`results/reports/reporter_report_*.html`
