## 新Agent接入适配工作梳理

### 6层适配清单
1. **agents.yaml** (必做, ~40行): +1 framework section, 含command模板/env/sandbox/preflight/compatible_languages/output_globs
2. **Docker镜像** (必做, 1-3行): docker/agents/Dockerfile Stage 1安装新Agent CLI
3. **Skill注入映射** (必做, 3行): subjects.go injectAgentNativeSkill() +1 case → 目录映射
4. **输出解析** (按需, 20-80行): adapter_cli.go parseAgentOutput() 新分支(工具调用+token)
5. **Session导出** (按需, 30-50行): 参考collectOpenCodeSessionExport(), 若stdout已有usage可跳过
6. **端到端验证** (必做): docker build + utbench run单样本 + trace检查

### 关键模板变量
- `{{.ContainerWorkdir}}` / `{{.ContainerPrompt}}` / `{{.ContainerOutput}}` — 容器内路径
- `{{.ModelID}}` / `{{.ModelEndpoint}}` / `{{.ModelAPIKeyEnv}}` — 模型配置

### 架构优势与瓶颈
- 优势: Subject三元组天然支持扩展, 笛卡尔积自动组合, 统一沙箱镜像共享, 模板化command
- 瓶颈: 输出解析是per-framework硬编码switch, Agent增多后膨胀, 长期应引入OutputParser接口

### 预估工时
- 最简(仅需YAML+镜像+3行Go): 2-3小时
- 完整(含自定义输出解析+session导出): 1-2天

## Claude Code vs Codex CLI 接入评估

### 结论（已修正）: Claude Code胜出, Codex CLI出局
- **Codex v0.80.0+限制**: 强制Responses API,不再支持chat/completions,第三方模型全不兼容
- **Claude Code多模型方案**: 各厂商均提供Anthropic兼容端点(`/anthropic`),只需3个环境变量(BASE_URL+AUTH_TOKEN+MODEL)
- **厂商兼容接口**: DeepSeek(api.deepseek.com/anthropic)、百炼(dashscope.aliyuncs.com/apps/anthropic)、智谱(open.bigmodel.cn/api/anthropic)、MiniMax(api.minimaxi.com/anthropic 国内/api.minimax.io 国际)、豆包(ark.cn-beijing.volces.com/api/coding Coding Plan或/api/compatible)
- **Claude Code headless**: `claude -p --bare --output-format stream-json --verbose --max-turns 50 --permission-mode bypassPermissions`
- **优势vs CodeBuddy**: 零配置文件(纯env注入)、NDJSON丰富事件流、原生total_cost_usd/token追踪
- **stream-json陷阱**: assistant事件同一message.id多次发射需去重; tool_result在user事件中不在assistant中; result字段是total_cost_usd不是cost_usd
- **6层适配**: agents.yaml + Dockerfile + injectAgentNativeSkill(.claude/skills/) + parseAgentOutput(stream-json) + sessionExport(按需) + smoke test
- **完整参考文档**: docs/CLAUDE_CODE_REFERENCE.md (已修正5处错误)
