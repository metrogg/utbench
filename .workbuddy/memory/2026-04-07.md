# 2026-04-07

## ut-bench 项目全面技术诊断

用户请求资深开发者视角的项目诊断。对整个 Python 评测链路做了深度代码审阅。

### 诊断要点
- 架构三段式 (Runner/Evaluator/Reporter) 清晰，dataclass contracts 管理规范
- Python 链路 AST 级 import 重写 + alias 机制设计巧妙
- Self-contained 分层评测策略是关键设计

### 发现的主要问题 (按优先级)
**P0:**
1. Runner 模块几乎无单元测试（仅2个文件，核心方法未覆盖）
2. subprocess 执行生成的测试代码缺少环境变量隔离（安全风险）
3. 集成测试依赖真实 results 目录

**P1:**
4. EvaluationResult dataclass 膨胀（17字段，mutation 7字段应拆分）
5. pipeline.py run() 是100行大函数，职责混杂
6. runner.py 中 datetime.utcnow() 已 deprecated（出现5次）
7. 重试无 jitter，多线程并发时可能惊群

**P2:**
8. subprocess timeout 硬编码，应从配置读取
9. mutmut monkey-patch 私有 multiprocessing API
10. loader.py legacy alias workaround 过多（技术债）
11. _safe_int bare except 过宽
