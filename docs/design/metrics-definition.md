# 评测指标定义

## 1. 指标体系概览

评测指标分为五类：

- 正确性
- 覆盖率
- 有效性
- 效率
- 工程质量

当前状态：

- Runner 已稳定产出效率类原始数据。
- Evaluator 在 Python 主线已落地正确性/覆盖率/变异指标。
- 其他语言指标仍待工具链接入。

## 2. 正确性指标

### 2.1 编译通过率（Compile Pass Rate）

定义：

```text
编译通过率 = 编译成功样本数 / 总样本数
```

意义：衡量生成代码的基础语法与依赖正确性。

### 2.2 测试执行通过率（Execution Pass Rate）

定义：

```text
执行通过率 = 测试执行成功样本数 / 编译通过样本数
```

意义：衡量生成测试在运行时的稳定性与断言正确性。

## 3. 覆盖率指标

### 3.1 行覆盖率（Line Coverage）

```text
行覆盖率 = 被执行代码行数 / 总代码行数
```

### 3.2 分支覆盖率（Branch Coverage）

```text
分支覆盖率 = 被覆盖分支数 / 总分支数
```

### 3.3 函数覆盖率（Function Coverage）

```text
函数覆盖率 = 被调用函数数 / 总函数数
```

建议阈值（当前配置参考）：

- 行覆盖率 ≥ 70%
- 分支覆盖率 ≥ 60%
- 函数覆盖率 ≥ 80%

## 4. 有效性指标

### 4.1 变异测试得分（Mutation Score）

```text
Mutation Score = 被杀死变异体数量 / 总变异体数量
```

意义：衡量测试用例发现缺陷的能力。

建议目标：≥ 85%。

## 5. 效率指标（Runner 已产出）

### 5.1 生成耗时（Generation Latency）

定义：单样本从发起 API 请求到收到响应的时延（毫秒）。

数据来源：`runner_summary_*.json` 中每条结果的 `latency_ms`。

### 5.2 Token 消耗（Token Usage）

定义：

```text
total_tokens = prompt_tokens + completion_tokens
```

数据来源：模型响应 `usage` 字段（若 provider 返回）。

## 6. 工程质量指标（规划）

### 6.1 Mock 准确率

关注是否正确隔离外部依赖（网络、文件、数据库等）。

### 6.2 断言充分性

关注断言是否覆盖核心行为和关键边界。

## 7. 汇总口径建议

- 按模型聚合：比较模型总体表现
- 按语言聚合：观察模型语言适配差异
- 按场景聚合：识别复杂场景短板
- 按样本粒度保留：支持问题追溯
