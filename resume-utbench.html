UT-Bench：多模型单元测试生成横向评测基准 核心开发者
一站式 AI Coding Agent 评测框架，支持 8+ 大模型（DeepSeek、MiniMax、豆包、GLM、Qwen、GPT 等）× 4 种编程语言（Python / Go / Java / C++）的多维横向评测。 创新提出 Framework × Model × Skill 三维评测模型，可量化分析 Agent 平台、底层模型、Skill 注入各自的贡献度。
  • 设计并实现 统一 Subject 抽象层（framework__model__skill），将纯模型 API、CLI Agent、Agent+Skill 三种评测模式纳入同一框架，支持 N×M×K 全组合自动展开
  • 构建 通用 CLI Agent 适配器，通过 agents.yaml 命令模板驱动，已集成 OpenCode、Claude Code 等主流 Agent，实现沙箱隔离执行（Docker 容器级隔离，支持 --network none、环境漂移拦截）
  • 实现 Skill 注入机制（prompt_append / workspace_mount / agent_native 三种模式），可量化评估 Skill 对 Agent 测试生成能力的提升幅度
  • 设计 四维评测指标体系：编译通过率 + 测试通过率 + 覆盖率 + 变异测试得分（综合分 = 0.3×编译 + 0.3×通过率 + 0.2×覆盖率 + 0.2×变异），超越传统 Pass@k 单一指标
  • 构建 多语言评测工具链：Python(pytest+mutmut) / Go(go test+go-mutesting) / Java(JUnit+JaCoCo+pitest) / C++(GoogleTest+gcov+mull)，覆盖编译、测试、覆盖率、变异测试全链路
  • 实现 Agent 过程可观测性：记录执行 trace、workspace diff、sandbox fingerprint，支持对 Agent 行为的细粒度分析与调试
  • 开发 Web 管理界面，支持评测任务配置、历史结果浏览、多轮次对比分析

UT-Bench：多模型单元测试生成横向评测基准 核心开发者
基于 Go 构建的 分布式评测 CLI 工具，采用五阶段流水线架构，支持多语言编译-测试-覆盖率-变异测试全自动化执行。 使用 Docker 实现评测沙箱隔离，SQLite 持久化存储，提供 Web 管理界面。
  • 独立设计并实现 Go 五阶段流水线架构（dataset → runner → evaluator → reporter → store），通过 orchestrator 编排，支持全链路执行和分阶段断点续跑
  • 实现 并发 Worker Pool + Checkpoint 增量执行机制，基于参数组合 SHA1 哈希实现断点续跑；支持指数退避重试、输出截断自动续写（max 3 retries）
  • 构建 Docker 沙箱评测引擎：每个 subject × sample 独立容器执行，支持语言级镜像选择、依赖自动安装、preflight 工具链自检、超时控制、网络隔离
  • 设计 统一数据契约层（internal/contracts），作为跨阶段数据流的 Single Source of Truth，JSON 序列化/反序列化贯穿全链路
  • 实现 SQLite v2 存储层：upsert 语义去重，支持 artifact 索引、多轮次评测结果对比、--reuse-generated 跳过重复 API 调用
  • 开发 Web 管理界面（嵌入式 HTTP Server + 静态资源），支持模型配置管理、数据库浏览、Docker 评测任务触发
  • 适配 8+ LLM API 提供商（DeepSeek、MiniMax、豆包、GLM、Qwen、GPT 等），统一请求/响应格式，处理各异 API 兼容性问题

使用建议

  • 投 AI Agent / 评测方向：使用版本 A，重点突出三维评测模型、Agent 适配器、Skill 注入、过程可观测性
  • 投后端 / 基础设施方向：使用版本 B，重点突出流水线架构、并发模型、Docker 沙箱、存储设计
  • 通用场景：使用版本 C，5 条要点精简有力，适合简历空间有限时使用
  • 面试话术：准备好讲解「为什么选 Go」「为什么用 Docker 沙箱」「三维评测模型的创新点」「变异测试为什么比单纯覆盖率更能反映测试质量」
  • 量化数据：如果有实际跑过的评测数据（评测了多少样本、多少模型组合、发现了什么结论），务必补充进去
