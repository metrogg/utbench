# ut-bench 数据集说明

## 目录结构

数据集采用 **语言 + 复杂度** 分层结构，按编程语言和代码复杂度分级组织：

```
dataset/
├── java/           # Java 语言测试样本
│   ├── simple/     # 简单级：纯函数、工具类
│   ├── medium/     # 中等级：类实例、接口 Mock
│   └── complex/     # 复杂级：边界条件、依赖复杂
├── python/         # Python 语言测试样本
│   ├── simple/
│   ├── medium/
│   └── complex/
├── go/             # Go 语言测试样本
│   ├── simple/
│   ├── medium/
│   └── complex/
├── cpp/            # C++ 语言测试样本
│   ├── simple/
│   ├── medium/
│   └── complex/
└── javascript/      # JavaScript 语言测试样本 (待补充)
    ├── simple/
    ├── medium/
    └── complex/
```

## 复杂度分级标准

| 级别 | 特征 | 样例 |
|------|------|------|
| **simple** | 纯函数、无状态操作、基础数据结构 | 字符串处理、数学计算、数组操作 |
| **medium** | 类实例、依赖注入、简单 Mock、接口测试 | 用户管理、订单服务、数据仓储 |
| **complex** | 边界条件、复杂依赖、多层抽象、外部调用 | 文件解析、网络请求、多线程 |

## 样本命名规范

样本文件命名格式：`{场景类型}_{语言}_{场景名}.{扩展名}`

示例：
- `simple_function_java_simple_function_0.java`
- `interface_mock_python_interface_mock_0.py`
- `boundary_go_boundary_0.go`
- `complex_dependency_cpp_complex_dependency_0.cpp`

## 评测维度

| 维度 | 指标 | 阈值 |
|------|------|------|
| 正确性 | 编译通过率、测试执行通过率 | ≥70% / ≥60% |
| 覆盖率 | 行覆盖率、分支覆盖率、函数覆盖率 | ≥70% / ≥60% / ≥80% |
| 有效性 | 变异测试得分 | ≥85% |
| 效率 | 生成耗时、Token 消耗 | - |
| 工程质量 | Mock 准确率、断言充分性 | - |

## 贡献新样本

新增样本需满足：

1. **自包含性**：样本代码不依赖外部复杂环境
2. **可测试性**：可生成有效的单元测试
3. **代表性**：覆盖典型场景和语言特性
4. **无外部依赖**：不依赖网络请求、数据库等外部系统

样本文件放在对应语言和复杂度目录下，命名遵循上述规范。
